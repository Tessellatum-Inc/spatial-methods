# Dynamic spatial models, filtering and data assimilation

## Purpose

A time-indexed spatial dataset is often generated by a system that evolves between observations. Data assimilation combines an evolving model with new measurements to estimate the current state and, when a forecast model is available, propagate that estimate forward.

This module explains the statistical architecture behind that process. It distinguishes:
- **Filtering:** estimating the current latent state using observations available up to the current time.
- **Smoothing:** retrospectively estimating past states using observations from both before and after those states.
- **Forecasting:** propagating a state estimate beyond the latest assimilation time using a specified evolution model.
- **Data assimilation:** repeatedly combining model evolution and observations, often as part of a forecast-analysis cycle.

These are related but not interchangeable operations. A filter or analysis update alone does not constitute a forecast system.

## 1. The state-space representation

Let the latent system state at discrete time \(t_k\) be \(\mathbf{x}_k\). A general Markov state-space model is

\[
\mathbf{x}_k=f_k(\mathbf{x}_{k-1},\mathbf{u}_k)+\mathbf{w}_k,
\]

\[
\mathbf{y}_k=h_k(\mathbf{x}_k)+\mathbf{v}_k,
\]

where \(f_k\) is the state-transition model, \(\mathbf{u}_k\) contains known controls or external forcing, \(\mathbf{w}_k\) is process noise, and \(h_k\) is the observation operator, with \(\mathbf{v}_k\) representing measurement or observation error.

A common baseline assumes zero-mean noises with covariances \(Q_k\) and \(R_k\). Independence between process noise, observation noise and prior state is a modelling assumption, not a universal fact. Correlated or biased errors require an explicit model.

The state is not necessarily the observed field itself. It may contain field values, gradients, velocities, source strengths, calibration parameters or other latent variables needed to make the evolution approximately Markovian.

## 2. Spatial observation operators

The observation operator connects the model state to what a sensor actually measures. It is not automatically an identity matrix.

For a gridded field \(\mathbf{x}\), a point sensor may approximately observe one grid cell, while a satellite pixel may measure a weighted spatial and spectral footprint. A mobile platform observes along a trajectory. A river gauge, road sensor, lidar point cloud, GNSS receiver and acoustic instrument each have different measurement geometry and physics.

For a linear observation model,

\[
\mathbf{y}_k=H_k\mathbf{x}_k+\mathbf{v}_k,
\]

the matrix \(H_k\) may encode interpolation, aggregation, projection from a high-dimensional state, or a sensor response. A nonlinear observation operator is written \(h_k(\mathbf{x}_k)\).

The operator must respect coordinate reference systems, units, temporal support, sensor footprint, datum and measurement definition. Mapping an observation to the nearest grid cell can be a poor approximation when the footprint spans many cells or when the state variable is not directly measured.

Observation coverage and observation error are separate issues. A missing observation provides no measurement update at that time; it does not imply that the latent state is zero or unchanged.

## 3. Bayesian filtering: prediction followed by update

Filtering propagates a probability distribution for the latent state. In Bayesian form:

**Forecast / prior step**

\[
p(\mathbf{x}_k\mid\mathbf{y}_{1:k-1})
=
\int
p(\mathbf{x}_k\mid\mathbf{x}_{k-1})
p(\mathbf{x}_{k-1}\mid\mathbf{y}_{1:k-1})
\,d\mathbf{x}_{k-1}.
\]

**Analysis / update step**

\[
p(\mathbf{x}_k\mid\mathbf{y}_{1:k})
\propto
p(\mathbf{y}_k\mid\mathbf{x}_k)
p(\mathbf{x}_k\mid\mathbf{y}_{1:k-1}).
\]

The forecast distribution represents the state before incorporating the current observation. The analysis distribution represents the state after the observation update. In operational data assimilation, this cycle repeats as new observations arrive.

The terms forecast and analysis are conventional in data assimilation. A forecast step can be very short and may simply advance the state from one observation time to the next. A long-range forecast requires a credible model and future forcing assumptions.

## 4. Linear Gaussian Kalman filtering

For the linear model

\[
\mathbf{x}_k=F_k\mathbf{x}_{k-1}+B_k\mathbf{u}_k+\mathbf{w}_k,
\qquad
\mathbf{y}_k=H_k\mathbf{x}_k+\mathbf{v}_k,
\]

with Gaussian independent noises, the prior mean and covariance propagate as

\[
\mathbf{x}_k^f=F_k\mathbf{x}_{k-1}^a+B_k\mathbf{u}_k,
\]

\[
P_k^f=F_kP_{k-1}^aF_k^\mathsf{T}+Q_k.
\]

The innovation and its covariance are

\[
\mathbf{d}_k=\mathbf{y}_k-H_k\mathbf{x}_k^f,
\qquad
S_k=H_kP_k^fH_k^\mathsf{T}+R_k.
\]

The Kalman gain is

\[
K_k=P_k^fH_k^\mathsf{T}S_k^{-1}.
\]

The analysis is

\[
\mathbf{x}_k^a=\mathbf{x}_k^f+K_k\mathbf{d}_k,
\]

\[
P_k^a=(I-K_kH_k)P_k^f.
\]

In numerical implementations, solve linear systems rather than explicitly forming \(S_k^{-1}\). The Joseph covariance form,

\[
P_k^a=(I-K_kH_k)P_k^f(I-K_kH_k)^\mathsf{T}
+K_kR_kK_k^\mathsf{T},
\]

is often preferred for better numerical preservation of symmetry and positive-semidefinite structure.

The Kalman filter is exact for the stated linear-Gaussian model. It is not exact merely because the equations are used on nonlinear dynamics or non-Gaussian errors.

## 5. Nonlinear and ensemble approximations

### Extended and unscented Kalman filters

The extended Kalman filter locally linearises the transition and observation functions using Jacobians. It can be efficient when nonlinearities are moderate and the local linear approximation is adequate. Strong curvature, poor Jacobians or highly non-Gaussian posteriors can make its Gaussian approximation unreliable.

The unscented Kalman filter propagates a deterministic set of sigma points through nonlinear functions and reconstructs approximate moments. It avoids explicit first-order Jacobians but remains a moment-based approximation; it does not represent arbitrary multimodal posteriors.

The repository implements EKF and scaled UKF single-step and sequence functions with additive noise and caller-supplied model functions/Jacobians. Their state and noise assumptions are narrower than a general geospatial navigation or environmental assimilation system.

### Ensemble Kalman filtering

For an ensemble of \(N\) forecast members, define the sample mean and anomalies:

\[
\bar{\mathbf{x}}^f=\frac{1}{N}\sum_{i=1}^{N}\mathbf{x}_i^f,
\qquad
A^f=[\mathbf{x}_1^f-\bar{\mathbf{x}}^f,\ldots,
\mathbf{x}_N^f-\bar{\mathbf{x}}^f].
\]

The sample forecast covariance is

\[
P^f\approx\frac{A^f(A^f)^\mathsf{T}}{N-1}.
\]

For a linear observation operator, the ensemble estimates the state-observation cross-covariance and observation covariance, giving the gain

\[
K=P_{xy}(P_{yy}+R)^{-1}.
\]

The stochastic EnKF updates members using perturbed observations; deterministic ensemble square-root methods transform ensemble anomalies without perturbing observations. These approaches are related but not identical algorithms.

An ensemble with \(N\) members has covariance rank at most \(N-1\). When the spatial state dimension is much larger than the ensemble size, spurious long-range sample correlations can dominate the update. Localization limits updates using distance or modelled dependence; inflation counteracts under-dispersion in some settings. Neither is a universal correction: localization can suppress real long-range dependence, and inflation can amplify model error.

The repository includes batch linear ETKF and stochastic EnKF analysis implementations. They are analysis steps; they do not supply the forecast model, ensemble propagation, localization, inflation or a complete cycling system.

## 6. Particle filtering and non-Gaussian states

Particle filters represent the posterior by weighted samples:

\[
p(\mathbf{x}_k\mid\mathbf{y}_{1:k})
\approx
\sum_{i=1}^{N}w_k^{(i)}
\delta_{\mathbf{x}_k^{(i)}}(\mathbf{x}_k),
\qquad
\sum_i w_k^{(i)}=1.
\]

Particles are propagated through the transition model and reweighted according to the observation likelihood. Resampling is used when weights become too concentrated. A common diagnostic is effective sample size,

\[
N_{\mathrm{eff}}=\frac{1}{\sum_i(w_k^{(i)})^2}.
\]

Particle methods can represent non-Gaussian and multimodal distributions, but in high-dimensional spatial systems they often suffer from weight degeneracy and require many particles. Resampling does not create new information and can reduce particle diversity.

The repository's bootstrap particle filter includes log-weight normalisation, effective-sample-size-triggered systematic resampling and stored particle histories. Its FFBSi companion is an offline trajectory smoother. These are teaching baselines, not a scalable high-dimensional geophysical particle-assimilation system.

## 7. Filtering, smoothing and forecasting

| Operation | Information used | Main purpose |
|---|---|---|
| Filtering | Observations through the current time \(k\) | Estimate the current state causally |
| Smoothing | Observations before and after a target time | Retrospectively refine past states |
| Forecasting | Current analysis plus transition model and future inputs | Estimate future states |
| Analysis update | Forecast prior plus current observations | Correct the current model state |

The Rauch–Tung–Striebel smoother is a backward pass for linear-Gaussian state-space models. It uses later filtered information to revise earlier estimates. An estimate smoothed using observations after time \(k\) was not available at time \(k\); using it in a real-time performance claim creates look-ahead leakage.

A filter can operate without a useful long-range forecast. Conversely, a forecast model can run without data assimilation, but it may drift away from reality. Assimilation is the repeated integration of observations and model evolution, not simply interpolation between measurements.

## 8. Spatial data assimilation: practical design issues

Spatial state dimension can be enormous. A gridded atmosphere, ocean, land-surface or urban system may have millions of state variables, while observations are sparse, irregular, asynchronous and heterogeneous.

Important design decisions include:

1. **State definition:** choose variables sufficient to represent the evolving system, not just the available observations.
2. **Transition dynamics:** encode transport, conservation, diffusion, reactions, sources and boundary conditions where relevant.
3. **Observation operator:** represent sensor geometry, footprint, aggregation and measurement physics.
4. **Error model:** distinguish observation error, model/process error, representativeness error and systematic bias.
5. **Temporal alignment:** account for acquisition time, latency, integration interval and asynchronous sensors.
6. **Scalability:** consider sparse matrices, low-rank methods, domain decomposition, ensembles, reduced-order states or hierarchical approximations.
7. **Physical constraints:** preserve units and coordinate meaning; impose conservation, positivity or other constraints only where scientifically justified.
8. **Diagnostics:** inspect innovations, innovation covariance, residual bias, spread-skill relationship, ensemble rank and spatially structured errors.

The innovation sequence is particularly informative. Persistent bias, incorrect innovation variance, spatial structure or temporal autocorrelation can reveal model and observation mismatch. A small analysis residual alone is not proof of a good model: a filter with an overconfident observation model may simply overfit each update.

## 9. Validation without information leakage

A state-estimation system must be evaluated in the mode in which it will be used.

- For **real-time filtering**, each estimate at \(t_k\) may use only data available by \(t_k\), including realistic delivery latency.
- For **smoothing**, retrospective data after \(t_k\) are allowed, but the result must be labelled as retrospective.
- For **forecasting**, issue forecasts from defined origins and score them at specified horizons against observations not used in the analysis.
- For **spatial transfer**, hold out locations or regions and test whether the observation network supports generalisation there.
- For **sensor transfer**, hold out instruments or acquisition campaigns where calibration and measurement differences matter.

Randomly splitting individual space-time observations can leak adjacent times, repeated measurements or shared sensor information across training and test sets. Use blocked, chronological, leave-location-out or combined designs according to the intended deployment claim.

Evaluate both state accuracy and uncertainty quality. Point-error metrics do not test calibration. Compare forecast spread with realised errors, assess interval coverage and sharpness, and stratify results by horizon, location, regime and observation density.

## 11. Limits and further development

This module explains the architecture and assumptions of data assimilation. It does not claim that the repository contains an operational spatial assimilation system. Existing implementations cover selected filtering, smoothing and analysis algorithms, but lack a unified spatial forecast model and cycling workflow, high-dimensional localization/inflation, comprehensive observation operators, model-error calibration, operational latency handling and application-specific physical constraints.

Further work should integrate a reproducible low-dimensional spatial state-space example first, then expand to advection-aware model propagation, heterogeneous observation operators, ensemble cycling, diagnostics and forecast verification. Each application requires domain-specific review of its governing dynamics and measurement model.
