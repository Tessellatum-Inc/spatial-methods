# Spatial Methods distribution kit

## Principle

Publish once to the canonical technical home, then adapt the discovery and member-facing framing for each channel. Do not create parallel copies that drift from the repository.

## Channel roles

| Channel | Primary job | Best format | Destination |
|---|---|---|---|
| GitHub | Canonical technical record, code, notebooks, sources and corrections | Exploration, lab, evidence register | Repository |
| Patreon | Guided member experience, navigation, companion material and participation | Welcome, exploration feature, lab companion, dispatch | Relevant Patreon destination |
| Newsletter | Retain attention and point readers to useful work | Short editorial letter with one central idea | Canonical exploration / Patreon |
| Medium | Searchable public discovery and longer-form editorial explanation | Standalone article with original analysis | Canonical exploration |
| LinkedIn | Professional discovery and discussion | Specific insight, diagram or application | Canonical exploration |
| YouTube | Demonstration and explanation when visual walkthrough adds value | Screen-based practical walkthrough or conceptual explainer | Canonical exploration |
| GitHub Discussions / Issues | Technical questions, corrections and contribution | Issue, discussion or pull request | Repository |

## Radar launch sequence

### 1. Canonical release
Publish and verify:
- Radar main exploration.
- Radar territory map.
- Sentinel-1 practical investigation.
- Radar source notes and evidence register.

### 2. Patreon
- Publish the Radar launch post.
- Link all canonical GitHub assets.
- Invite one bounded question through the Curiosity Desk.
- Do not imply a scene-specific result until one has been processed and reviewed.

### 3. Newsletter
Subject: **Radar is not one subject. Here's how to find your way in.**

Lead with the distinction between Earth-observation SAR, weather radar and radar engineering. Explain that the new exploration is question-led, not a fixed course. Link to the territory map and first Sentinel-1 investigation.

### 4. Medium
Working title: **A radar image is not a photograph: how to start reading Sentinel-1**

Explain active sensing, backscatter, geometry and why brightness alone is not a land-cover label. Use the Radar exploration as the deeper reference. Avoid copying the technical guide verbatim; the article should contribute a clear standalone explanation.

### 5. LinkedIn
Opening idea: “A dark patch in a radar image is not automatically water. A bright patch is not automatically a building. The measurement has a physics, a geometry and a processing history.”

Develop this into a concise discussion of why spatial interpretation requires more than visual pattern matching. Link the practical investigation.

### 6. YouTube
Only produce a video if a screen demonstration adds value. A useful first video would show:
- finding a Sentinel-1 scene or RTC product;
- inspecting product metadata;
- opening the image;
- recording observations and uncertainty.

Do not present the video as a complete SAR processing tutorial unless the full workflow is actually demonstrated and checked.

## Reusable release checklist

- [ ] Canonical GitHub assets are committed and links verified.
- [ ] Claims match the evidence register.
- [ ] Third-party data, images and quotations comply with licences and attribution.
- [ ] Patreon post points to canonical assets and makes the member action clear.
- [ ] Public channel copy adds context rather than duplicating the same text.
- [ ] Every channel has one useful next action.
- [ ] Publication date is set only after final review.
- [ ] Corrections and updates route back to the canonical source.
