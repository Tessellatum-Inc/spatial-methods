# Martinez–Rueda polygon overlay — staged implementation

The implementation provides x-ordered endpoint processing with an augmented dynamic y-interval treap status, cross-source segment candidate filtering, exact intersection/contact noding, grouped multiway node events, exact rational left/right side classification for intersection/union/difference/XOR, and directed-fragment stitching into closed output rings. The interval treap supports expected-logarithmic insertion/removal and expected O(log n + k) interval-overlap reporting. It prunes y-disjoint active segments before exact intersection tests. A min-heap expires segments whose x-intervals have ended, avoiding a linear scan of the active set at every new left endpoint. Split parameters are exact `Fraction` values throughout sorting and deduplication.

Input supports one shell plus zero or more disjoint, non-nested holes per source. Each sweep result also exposes `node_events`, which coalesces pairwise crossing/contact reports at one exact coordinate and lists all incident segment IDs; `intersection_events` remains the proper-crossing-only compatibility view. Output includes both a flat collection of oriented rings (shells counter-clockwise, holes clockwise) and a Polygon-like collection with each hole assigned to its smallest containing shell. Disconnected results and islands inside holes are represented as separate polygon components.

**Important distinction:** this is an augmented interval broad phase, not the full Martinez–Rueda neighbour-ordered status with dynamically scheduled intersection events. Dense or heavily overlapping data can still require quadratic candidate checks. Inputs do not support multiple independent shells per source. Positive-length collinear overlaps are now split at both overlap endpoints and classified by exact side probes; coincident output fragments are deduplicated before stitching. This extends shared-boundary handling, but does not yet make the implementation a full neighbour-event Martinez kernel or a complete exact-topology engine. Pairwise contact reports are coalesced into exact-coordinate node events, but a full dynamically scheduled multiway event queue and broader degeneracy guarantees remain open. Shell/hole assembly is a bounded ring-grouping step, not a general-purpose geometry validity or repair engine. The input vertices, segment predicates, split parameters and generated intersection nodes are represented as exact `Fraction` coordinates derived from the decimal representations of input values. This preserves large integer coordinates and rational crossing locations throughout noding. Split parameters remain exact rationals during sorting and deduplication, so distinct nearby crossings are not collapsed merely because their parameter separation is below epsilon. Fragment classification constructs exact rational side probes whose offset is bounded by the exact clearance to every non-collinear source boundary. The offset does not depend on the public epsilon, so a narrow face is not skipped merely because its width is below that tolerance. It retains only edges across which the Boolean result changes, orienting the result interior to the left. Ring simplicity now uses exact orientation and segment-intersection predicates, and point-in-ring uses an exact even-odd ray test with boundary points treated as outside. The x/y interval broad phase uses epsilon-expanded bounds only to avoid missing candidate pairs; final intersection/contact decisions are exact. Contour successor selection now uses exact rational polar ordering rather than floating-point angles. The remaining proof and stress-test gap is complete handling of every multiway degeneracy, not the orientation or angular comparison predicates. Signed shoelace area, ring orientation and zero-area rejection now use exact rational arithmetic over decimal coordinate representations.

Run `python -m pytest -q` in this directory.

## Polygon component assembly

`boolean_overlay_rings` returns both the flat oriented `rings` collection and a `polygons` collection. Each polygon entry contains one CCW `shell` and zero or more directly assigned CW `holes`. A positive-area island inside a hole is emitted as a separate polygon component. Hole ownership is assigned to the smallest-area shell that contains a hole vertex.
