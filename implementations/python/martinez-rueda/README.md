# Martinez–Rueda polygon overlay — staged implementation

The implementation provides x-ordered endpoint processing with an augmented dynamic y-interval treap status, cross-source segment candidate filtering, segment intersections and splitting, midpoint inside/outside classification for intersection/union/difference/XOR, and directed-fragment stitching into closed output rings. The interval treap supports expected-logarithmic insertion/removal and expected O(log n + k) interval-overlap reporting. It prunes y-disjoint active segments before exact intersection tests.

Input supports one shell plus zero or more disjoint, non-nested holes per source. Output includes both a flat collection of oriented rings (shells counter-clockwise, holes clockwise) and a Polygon-like collection with each hole assigned to its smallest containing shell. Disconnected results and islands inside holes are represented as separate polygon components.

**Important distinction:** this is an augmented interval broad phase, not the full Martinez–Rueda neighbour-ordered status with dynamically scheduled intersection events. Dense or heavily overlapping data can still require quadratic candidate checks. Inputs do not support multiple independent shells per source. Positive-length collinear overlaps and touching/near-coincident boundary configurations are not fully supported. Shell/hole assembly is a bounded ring-grouping step, not a general-purpose geometry validity or repair engine. The segment-pair determinant and intersection-parameter calculations use exact rational arithmetic over the decimal representations of input coordinates; coordinates are converted back to floats for downstream overlay. Ring simplicity now uses exact orientation and segment-intersection predicates, and point-in-ring uses an exact even-odd ray test with boundary points treated as outside. Endpoint tolerance, fragment stitching and shell/hole assembly still include floating-point operations, so the overlay as a whole is not an exact-topology engine. Signed shoelace area, ring orientation and zero-area rejection now use exact rational arithmetic over decimal coordinate representations.

Run `python -m pytest -q` in this directory.

## Polygon component assembly

`boolean_overlay_rings` returns both the flat oriented `rings` collection and a `polygons` collection. Each polygon entry contains one CCW `shell` and zero or more directly assigned CW `holes`. A positive-area island inside a hole is emitted as a separate polygon component. Hole ownership is assigned to the smallest-area shell that contains a hole vertex.
